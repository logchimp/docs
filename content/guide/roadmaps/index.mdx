## Overview

Roadmaps represent the stages in the lifecycle of a post. Customers use them to see the status of the feature requests and suggestions they submit. At a glance, a customer can see whether a post is in **Backlog**, **Under review**, **In progress**, or **Completed**.

You create these stages yourself, so your roadmap can use different names. Your team uses roadmaps to organize posts and track their progress. Customers see a roadmap only after you set it to public. For steps, see [Create roadmaps](#create-roadmaps).

Roadmaps give meaningful context to daily project work, which can help motivate the team members doing it.

## Dashboard

Create and/or manage roadmaps in the **Dashboard > Roadmaps page**.

### Create roadmaps

<Alert type="tip">
	You need **`roadmap:create`** permission to perform this action.
</Alert>

Creating a new roadmap will set to private by-default. You can toggle the **Display** settings to change visibility it public.

### Update roadmaps

<Alert type="tip">
	You need **`roadmap:update`** permission to perform this action.
</Alert>

### Delete roadmaps

<Alert type="tip">
	You need **`roadmap:destroy`** permission to perform this action.
</Alert>
